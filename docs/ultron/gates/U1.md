## Entregas concretas

### `src/ultron/registry/__init__.py`

- `Registry` class (async, com aiosqlite)
- Schema SQL com tabelas `manifests`, `manifests_fts` (FTS5), `migrations`, `audit`
- WAL journal mode + foreign keys
- Operações: `publish`, `get`, `list_all`, `search` (FTS5 + filtros), `delete`, `count`, `stats`, `recent_audit`
- SHA-256 hash do payload JSON canônico para imutabilidade

### `src/ultron/api/`

- `create_app()` singleton FastAPI com lifespan
- `registry_router.py` com endpoints JSON:
  - `GET /api/v1/manifests?kind&limit&offset`
  - `GET /api/v1/manifests/search?q&kind&capability&publisher&license&risk&status&runtime`
  - `GET /api/v1/manifests/{id}` (com `@version` opcional)
  - `GET /api/v1/stats`, `GET /api/v1/audit/recent`
  - `GET /api/v1/health`

### `src/ultron/portal/`

- Templates Jinja2: `base.html`, `index.html`, `browse.html`, `manifest.html`, `graph.html`, `audit.html`
- Static: `ultron.css` (CSS variables + Obsidian palette), `ultron.js` (palette + theme toggle), `graph.js` (Cytoscape loader)
- Páginas HTML servidas em `/`, `/browse`, `/manifest/{id}`, `/graph`, `/audit`
- Design Obsidian: 3-col layout, dark default `#1e1e1e` / accent `#7f6df2`, Inter + JetBrains Mono, command palette ⌘K, backlinks

### `tests/integration/`

- `test_registry.py` — 20 testes (publish/get/list/search/delete/count/stats/audit/imutabilidade/diacríticos)
- `test_api_health.py` — 9 testes (health/openapi/index/browse/audit/css/search/list/404)

## Decisões

- **DEC-U-009** — Portal stack: HTMX-free (descartado por simplicidade) + Jinja2 + vanilla JS + Cytoscape (via CDN, com fallback HTML). Sem build step, sem Node.
- **Resolver imports circulares** entre `ultron.api` e `ultron.portal` via lazy import dentro de funções (`_get_registry_singleton()`)
- **FTS5 sem `content=manifests`** — testes simples, triggers manuais no delete. Para escala, adicionar triggers automáticos em migration v2
